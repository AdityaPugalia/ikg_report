\section{Evaluation}
\label{sec:next}

\subsection{Current Issues}

Every miss in the FinanceBench and Multi-Doc fall into six kinds:

\begin{enumerate}
\item \textbf{Fixed caps instead of a value rule.} The loop stops on task, depth, route and round caps. 
\item \textbf{The cited figure is not the target.} Grounding checks that a quote is printed, not that it is the thing asked.
\item \textbf{Units on computed figures.} A figure the answer stage computes in code carries no unit, so the evaluator treats it as base units and scales it wrongly.
\item \textbf{The question's or the filing's definition differ from the graph's formula.} For instance Nike's inventory turnover is defined in the question over \emph{average} inventory but the graph's ending-inventory identity was used. 
\item \textbf{Shape.} The evaluator collapses a multi-figure text answer to one number when the question's wording looks numeric.
\item \textbf{Judgement and reading.} Of 17 wrong FinanceBench text answers, 6 are a verdict against the gold on a judgement call (E.g. ``is capital intensity high?''). The numeric values are computed correctly but the judgement for those answers differed from what the gold had suggested.
\end{enumerate}


\subsection{Improvement}

None of the above mentioned problems stem from retrieval but come from the agent loop.
\begin{enumerate}
\item \textbf{Value based expansion}: A simple improvement on the model call caps would be to just increase the limit. Another method that I am currently exploring is estimating the value gained from expanding further by taking into account the likelihoods of the fact being present in a given document, in the top ranked chunks presented to the model, and the likelihood of the model actually using the correct value from the provided chunks. The results for this are not out yet
\item \textbf{LLM evaluator}: Issues (2), (3), and (5) can simply be solved by having an LLM evaluator in the loop along with the code checks to ensure the validity of the answer.
\item \textbf{Filing Definition mismatch}: The solution to this is a simple rule to override the the formula to be used by the LLMs.
\end{enumerate}
